Day 25 · Open/local models and practical adaptation: LoRA, QLoRA, and SFT

5:30 p.m.–10:00 p.m. · 240 instructional minutes · 30-minute break

Back to hub

Tonight's goal

Explain why a team may adapt a small open model instead of only prompting or using RAG, then run or inspect a constrained PEFT workflow from 4-bit loading through SFT and adapter evaluation.

Success criteria:
  • Students trace a small/open model through quantized loading, LoRA attachment, instruction dataset formatting, SFT, adapter saving, and base-versus-SFT comparison, with train[:64], a short run, CPU inference, or a precomputed fallback when training is unavailable.

Session outline

What to do today

  1. Retrieval and goals: Name the controlled fields in a reproducible model experiment. | Explain why open weights do not remove licensing, privacy, or safety obligations. | Recall the difference between prompting, RAG, and changing model behavior.
  2. Worked example: Start with the existing Qwen/Qwen2.5-0.5B-Instruct or similarly practical small model, load it in 4-bit NF4 with bitsandbytes, attach LoRA adapters to appropriate attention projections, format a tiny instruction dataset such as train[:64], run or inspect a one-epoch/10–20-step SFT profile, save the adapter, and compare base and SFT outputs.
  3. Guided practice: Hosted/open route comparison; full fine-tuning versus PEFT; LoRA and QLoRA; 4-bit bitsandbytes/NF4 loading; prepare_model_for_kbit_training or the equivalent current workflow; attention target-module choice; instruction dataset formatting; SFT; adapter save/load/merge inspection; base/SFT comparison.
  4. Assessment: Adaptation configuration and base-versus-SFT evidence record
  5. Homework: Complete the adapter configuration record, run or inspect the reduced SFT route, and submit fixed-prompt base-versus-SFT evidence. (50 minutes)
