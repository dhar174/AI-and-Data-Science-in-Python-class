Course expectations

Adult beginners and career changers with mixed technical backgrounds

Prerequisites and Technology

  • No prior data-science credential is required.
  • Students need basic computer-file skills and willingness to practise programming and quantitative reasoning.
  • A CPU-capable Windows, macOS, Linux, or Chromebook route is sufficient for required work; GPU access is optional.
  • Required software and accounts are introduced through reproducible setup checks. Paid APIs are never the only route.
  • The instructor supplies local notebooks, response fixtures, static walkthroughs, or direct-shared files when public access, accounts, hardware, or network service is unavailable.
  • Students must never place credentials or private data in notebooks, source code, screenshots, or submissions.

Learning Outcomes

By the end of the course, students will be able to:

  1. Frame a data problem and build a reproducible evidence workflow from acquisition through communication.
  2. Use Python, NumPy, pandas, SQL, statistics, and visualization to inspect and prepare data.
  3. Build and evaluate leakage-aware classical models, including principled hyperparameter optimization.
  4. Implement neural workflows in PyTorch and explain tensors, gradients, optimization, regularization, CNNs, transfer learning, sequences, and attention.
  5. Compare selected advanced architectures without overstating survey-level exposure as implementation mastery.
  6. Build and evaluate prompts, chains, memory, RAG, vector search, conversational systems, and bounded tool-using agents.
  7. Demonstrate progressively deployable artifacts: reproducible analysis, repeatable model inference, and an evaluated AI application.
  8. Evaluate correctness, grounding, robustness, privacy, security, bias, cost, accessibility, human oversight, and residual risk.

Capstone Checkpoints

  • Module 1: domain (Day 1), dataset risk (Day 3), problem and baseline (Day 5), selection protocol (Day 7), design review (Day 9), build review (Day 10), showcase (Day 11).
  • Module 2: problem family (Day 1), data/task feasibility (Day 3), architecture and experiment plan (Days 4–6), environment record (Day 7), model card (Day 9), build gate (Day 10), showcase (Day 11).
  • Module 3: constraints (Day 2), model/adaptation route (Day 3), SFT/DPO comparison and evaluation cases (Day 4), formal proposal (Day 5), RAG/vector/tool checkpoints (Days 6–8), route-specific full evaluation (Day 9), safety and adaptation-risk gate (Day 10), showcase (Day 11).

Group work is permitted, but every student must submit an individual explanation, identify one personal contribution, reproduce one technical step, and answer an instructor question.

Submission, Feedback, and Resubmission

  • Labs are normally due before the next class unless the daily plan states otherwise.
  • Capstone milestones receive formative feedback and may be revised before the module deadline.
  • A late submission should include a short recovery plan; documented access, health, work, or caregiving barriers are handled through the course support process.
  • Students may resubmit one applied lab per module after correcting feedback and annotating what changed.
  • A capstone that misses a required validity, privacy, credential, or reproducibility gate must be corrected before it can receive passing technical credit.

Responsible AI and Academic Integrity

Permitted AI use must be disclosed. Students remain responsible for verification, citations, calculations, code, privacy, and submitted reasoning. Fabricated evidence, undisclosed copying, exposed credentials, use of private data without authority, or presentation of unverified AI output as fact is not acceptable. Course tools must be used within the assigned permission boundary.

Accessibility and Learner Support

The course uses predictable routines, vocabulary support, diagrams, spoken explanation, executable examples, starter notebooks, chunked instructions, CPU/offline alternatives, and multiple response routes when response mode is not the construct. Required media must have a transcript or equivalent summary; visual resources require a described equivalent and non-color cues. UDL reduces common barriers but does not replace individualized accommodations or specialist support.
